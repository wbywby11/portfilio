## 二、已确认差异与根因

### 2.1 有效资产数首日差异（最高优先级，~50%贡献）

**现象**：2014-01-31 计算日
- 生成组：有效资产数 = 0
- 对照组：有效资产数 = 9

**根因**：**输入数据起始日期不一致**

- 文档 B.4.2：资产历史不足 260 天不参与动量（标记「无效」）
- step1 逻辑：`valid_count >= min_history` 才计入有效资产
- 若系统 `data_feed.prices` 起始于 2014-01-02，则 2014-01-31 仅约 20 个交易日，不足 260 天
- 对照组 `daily_px.xlsx` 可能从 2006 年或更早开始，故首日即有 9 个有效资产

**影响**：N 不同导致反转得分基数差（N=9 vs 12，得分上限 18 vs 24），选股结果不同。

**修复建议**：
1. 统一输入：使用与对照组相同的 `daily_px.xlsx`，或确保回测数据起始日至少早于 2014-01-31 前 260 个交易日
2. 检查 `data_feed.prices` 各资产 `first_valid_index()`，确认历史长度 ≥ 260

### 2.2 资产命名格式差异（已修复）

**现象**：
- 生成组：入选矩阵列名为代码（SZ399006, HSTECH, SPX, GDAXI...）
- 对照组：列名为中文（创业板指, 恒生科技, 标普500, 德国DAX...）

**根因**：导出时未将资产代码映射为中文名

**修复**：已更新 `hybrid_momentum_export.py`：
- `export_selection_results` 增加 `asset_names` 参数
- 选择汇总、入选矩阵、入选状态矩阵、动量/反转排名详情均使用中文名输出

---

### 2.3 月末日期差异

**现象**：最后一行计算日
- 生成组：2026-02-03
- 对照组：2026-02-27

**根因**：月末计算日逻辑或数据末端不同
- 生成组：`prices.index` 的 month_end 可能为 2026-02-03（数据末日期）
- 对照组：`trade_dates.xlsx` 或 `daily_px.xlsx` 覆盖到 2026-02-27

**修复建议**：检查回测数据末端日期，确保与对照组一致

---

### 2.4 缺失值与边界处理（~20%贡献）

**现象**：生成组某些资产（如黄金）动量得分 14 vs 对照组 0

**可能原因**：
- 文档 B.4.1：价格缺失收益率 NaN，组合 vol 用 fillna(0)
- 因子计算：`pct_change()` 产生 NaN，`rolling.std()` 忽略 NaN，若窗口内 NaN 多则得分 0
- 生成组数据可能更完整或 fillna 更激进

**修复建议**：统一 NaN 处理策略，与文档 B.4.1/B.4.2 一致

---

### 2.5 因子计算数值细节（~15%贡献）

**可能差异**：
- 动量：MOM 用简单回报 vs log 回报；MACD win_long=250 是否一致
- 反转：`skew(bias=False)` vs `bias=True`（样本 skew）
- 排名：`rank(method='min')` vs `method='average'`（平局处理）

**修复建议**：单日期调试（如 2014-02-28），输出中间因子（MOM、MACD、偏度等），与对照组逐项比对

---

### 2.6 调仓日期与窗口对齐（~10%贡献）

**可能原因**：`trade_dates.xlsx` 版本不同，或 base_date 对齐差

**修复**：已使用 `portfilio-end/data/trade_dates.xlsx` 统一交易日历

### 6.4 2014 年初零波动根因（数据主导）

- **生成组**：`valid_assets=0`（数据起始不足 260 天）→ 权重全 0 → `port_vol=0`、`scale=1` → 零暴露、零收益、零波动。
- **对照组**：数据更早，2014-01-31 有 9 个有效资产 → 正常权重与波动。
- **根本原因**：输入数据起始日期不一致；逻辑对齐后，在**相同数据**下行为一致。

### 6.5 彻底消除波动率差异的检查清单

1. **数据完全统一**：同一价格序列、同一收益率计算。
2. **资产选择规则完全相同**：动量/波动率阈值、窗口长度、反转平局规则。
3. **优化模块完全复现**：同一协方差估计、同一求解器、同一约束。
4. **波动率公式 + 缩放逻辑**：`fillna_zero=False`，`weight_caps` 默认 1.0。
5. **单元测试**：每个日期 `assert |生成_vol - 对照_vol| < 1e-6`。

## 七、权重正确但净值/调仓差异大：执行过程排查

当**权重计算结果与对照组一致**，但**实际净值和调仓存在较大差异**时，问题在执行层（step3 等价逻辑）。

### 7.1 执行诊断日志

`hybrid_momentum_engine` 在回测开始前输出 `[混合动量-执行诊断]` 日志，便于与 step3 对照组对比：

- **回测日数**：`all_dates` 长度（来自 `prices.index`）
- **起止日期**：回测区间
- **调仓日数**：`rebalance_map` 条数
- **首/末调仓日**：与 step3 的 `adjust_date` 应对齐
- **asset_returns 覆盖**：有收益率的日期数（应为 回测日数-1）
- **前5/后5调仓日**：与 step3 的 `rebalance_map` 逐日比对
- **初始建仓日、初始总杠杆、初始权重**：与 step3 的 `weights_df.iloc[0]` 对应

### 7.2 常见差异根因

| 根因 | 现象 | 排查方法 |
|------|------|----------|
| **回测日期序列不同** | 每日净值行数 3127 vs 3145 | 对比 `all_dates` 与 step3 的 `backtest_dates`；step3 用「资产日历」（daily_px.xlsx 的 index），生成组用 API 返回的 prices.index，若后者为单一交易日历则日期更少 |
| **调仓执行日不一致** | 调仓日错位、净值曲线错位 | 对比 `rebalance_map` 的 key 与 step3 的 `adjust_date`；依赖 `trade_dates.xlsx` 一致 |
| **汇率 key 不匹配** | 非 CNH 资产净值偏差 | `config.fx_rates` 按资产代码 key，step3 按资产中文名；需确保映射一致 |
| **波动率冲突检查** | 波动率重置触发/执行日不同 | 已对齐：仅当 `date in trade_dates_set` 时才把 date 加入冲突检查 |

### 7.3 修复建议

1. **统一价格日历**：确保 `data_feed.prices` 的 index 与 step3 的 `daily_px.xlsx` 一致（资产日历 = 各资产交易日并集）。若 API 返回的是单一交易日历，需在数据层扩展为资产日历。
2. **统一交易日历**：`portfilio-end/data/trade_dates.xlsx` 与 step3 使用的 `trade_dates.xlsx` 一致。
3. **对照执行诊断**：运行 step3 与 hybrid 后，逐项对比上述诊断输出。
