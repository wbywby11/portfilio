# 数据层与集合全景

本文档是系统 MongoDB 数据库（库名 asset_allocation，本地端口 27018）的集合地图，按业务域分组说明每个集合的用途。数据探查、导入开发、Agent 数据工具调用、排查数据问题时先查本文档。集合名统一由 `app/config/collections.py` 的 COL_* 常量声明，代码中禁止硬编码。

## 一、行情与基础数据域

| 集合 | 用途 |
|---|---|
| `assets` | 资产档案（代码、名称、类别、上市日期等），导入需符合 Asset 模型字段枚举 |
| `asset_prices` | 日频行情（收盘价为主），全系统策略/回测/监控的核心数据源，含防重复索引加固 |
| `fx_rates` | 汇率数据（USD/JPY 等），跨境资产估值用 |
| `trade_dates` | 交易日历，月末信号日历、调仓排期、T+N 生效计算的基础 |
| `factor_panel` | 因子截面面板（按 `dataset` 分区，多个数据产品共用），独立策略的选券/选样输入 |

## 二、策略配置域

| 集合 | 用途 |
|---|---|
| `strategy_models` | 策略模型实例（composition 三层配置 + 参数），系统策略运行的主表 |
| `model_templates` | 策略模板注册表（code 唯一约束），内置模板启动时初始化 |
| `strategy_param_versions` | 策略参数版本历史 |
| `subjective_overrides` | 主观权重覆盖（人工干预记录） |
| `sharpe_rebalance_weights` | sharpe_18 研究员策略调仓权重 |

| `monitor_states` | 监控步进状态快照（断点续跑） |

|---|---|

## 九、数据管理纪律

1. **导入定位**：数据导入脚本定位为临时脚本（scripts/ 下），不属于系统核心体系；导入须幂等、可验证；
2. **导入审计**：所有导入写 `_import_audit_log`，可通过 Agent `query_import_logs` 工具溯源；
3. **防重复**：行情类集合有防重复索引加固，导入前查重；
4. **资产枚举**：资产导入字段必须符合 Asset 模型枚举（asset_class 等），错值会被校验拦截；
5. **数据质量**：Agent `check_data_quality` 工具检查重复/缺失/陈旧（is_stale），行情滞后超过阈值会提示补数据。
