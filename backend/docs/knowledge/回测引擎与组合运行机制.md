# 回测引擎与组合运行机制

本文档描述系统回测引擎（BacktestEngine）、三层组合流水线（CompositionPipeline）、母组合两段式运行（composite_runner）与产品层（product_layer）的机制与协作关系。涉及回测结果解读、组合构建、日常监控复用引擎逻辑时以本文档为准。

## 一、BacktestEngine：事件驱动核心层

`app/backtesting/engine.py` 是与模式无关的事件驱动引擎，主循环为：

```
价格数据流（DataFeed）
  → 信号时点判定（execution_bar，ScheduleResolver 调仓日历）
  → 权重构建（CompositionPipeline / IStrategy）
  → 成交模拟（ExecutionEngine：佣金/滑点）
  → 风险约束（RiskManager）
  → NAV 累积 + 快照/交易记录
```

**同一引擎支撑三种模式**（核心设计）：
1. **全量回测**：历史区间逐日推演；
2. **日常监控**：日级步进（monitor 模块复用，保证监控与回测逻辑同源）；
3. **模拟交易**：组合实盘模拟（sim_trade_engine 复用）。

这意味着回测、监控、模拟交易三者的信号/执行/风控逻辑完全一致，不会出现"回测与监控口径不同"的问题。

**引擎层波动率定标**（vol_targeting）：双向定标 clip(target/vol, 0.1, 5.0)，可向上加杠杆至 5 倍——与控制器层"只降不升"的风险阀语义不同（详见《选择层与风控层模块说明》双轨机制警示）。

## 二、CompositionPipeline：三层统一入口

`app/backtesting/composition_pipeline.py` 是所有策略的统一运行入口，实现 IStrategy 接口：

```
[Selection 可选] → Allocation 必选 → [PostProcess]
```

**编排原则**：
- Allocation 必选：每次调仓都计算权重；
- Selection 可选：`composition["selector"]` 为 None 时跳过；
- Control 可选：通过 `CONTROL_REGISTRY` 委托注册表管理，不在 Pipeline 内实现；
- 选择层参数（selector_type、asset_selection_count 等）通过 `composition["selection_params"]` 路由到选择器。

**数据输入**：`data_feed.py` 从 MongoDB 行情集合构建价格矩阵，含防重复索引加固。

## 三、母组合两段式运行（composite_runner）

`app/portfolio/composite_runner.py` 处理多子策略母组合，采用"统一运行路径"设计：

**两段式流程**：
1. **第一段**：各子策略独立回测，产出子策略 NAV 序列；
2. **第二段**：
   - 子策略 NAV 作为**合成资产价格**（`app/backtesting/synthetic_feed.py`）；
   - 母层权重由 `PortfolioWeightAllocator` 决定（固定权重/动态调权）；
   - 合成资产 + allocator 走同一个 CompositionPipeline 与 BacktestEngine，与单策略回测**共用信号/执行/风控逻辑**。

**与旧路径（composite_engine）的可解释差异**：
- 成立初期权重：新路径前 delay 日以初始权重计算，旧路径按持仓市值即时建仓；
- 交易成本：母层成本由母层参数独立控制（commission_rate/slippage，默认 0）；
- 权重漂移：`weight_drift=False` 时新路径每日复仓恒定权重，旧路径以净值漂移后展示值计算。

## 四、产品层（product_layer）

`app/backtesting/product_layer.py` 是策略之上的最终产品包装，三维度构成：**策略 + 债券专户 + 现金**。

**权重分配**（二元一次方程求解）：
- 现金固定：`w_cash = cash_fixed`（默认 15%）；
- 约束一：`w_strategy + w_bond = 1 - cash_fixed`；
- 约束二：`w_strategy × σ_strategy + w_bond × σ_bond = vol_target`（组合波动达标）；
- 解：`w_strategy = (vol_target - risk_budget × σ_bond) / (σ_strategy - σ_bond)`；
- 边界约束：`w_strategy ∈ [0, risk_budget]`。

**运行规则**：月度调仓，权重 shift(1) 延迟一日生效（避免未来函数）。

**启用方式**：策略模型的 `weight_model_params` 中配置 `product_layer` 字段（enabled/controller=vol_target/vol_target/cash_fixed/vol_window/bond_code/cash_code 等）。四象限策略即产品层的典型应用。

## 五、回测记录与分析

- 回测记录落 `backtest_records` 集合（状态、参数快照、指标）；
- `analytics.py` / `portfolio_analytics.py` 计算年化收益/波动/夏普/最大回撤等指标；
- `risk.py`（RiskManager）在引擎层执行风险约束；
- 回归基准：原型基线 NAV 归档于 `tests/fixtures/baselines/`，重构后必须对齐。
