# 因子打分指数类策略详解

> 覆盖两个策略：`bond_factor_score_index`（债券券池因子打分指数-凤凰50）、`factor_score_index`（因子打分指数-A股质量成长截面）。
> 本文所有数字均取自**当前库内实测**与代码常量，不引用外部资料。

---

## 零、先用一句话分清这两个策略

两个策略是**同一套骨架、不同打分规则**的两个实例：

| | 债券券池因子打分指数 | 因子打分指数 |
|---|---|---|
| 策略码 | `bond_factor_score_index` | `factor_score_index` |
| 选什么 | 548 只债券里选 **60 只** | 203 只A股里选 **50 只** |
| 打分法 | 名次分 + 距目标分，**加权**合成 | winsorize + min-max，**直接相加** |
| 硬约束 | 券池分组 + **单发行人限额** | **行业限额** |
| 怎么配权重 | 一律**等权 1/N** | 总市值 / 自由流通市值 / 等权，三选一 |
| 调样节奏 | 季度（28 期截面） | 随截面（当前仅 1 期） |
| 产品定位 | 复现指数编制规则 | 复现选股指数编制规则 |

一句话概括：**先给每只标的打分，再按规则筛出一篮子，最后按固定口径配权重，一季不动等下次调样。**

---

## 一、共同的骨架

两个策略都是 `strategy_form="standalone"` 的**打包独立形态**。理解这个形态，比理解任何公式都重要。

### 1.1 传统策略 vs 打包独立策略

系统里常规策略是「积木式」拼装：

```
selector（选哪些标的，如 sel_sharpe）
    ↓
allocator（怎么配权重，如 risk_parity）
    ↓
controller（风控覆写，如 ctrl_rolling_vol）
```

而这两个策略把三层全部内化在策略包里，`composition` 声明为：

```python
composition = {
    "selector": None,
    "allocator": "factor_score_index",   # 自己就是 allocator
    "controller": None,
    "schedule": {"rebalance_freq": "daily", "execution_delay": 0},
}
```

**为什么这样做**：指数编制规则是「选样—赋权」一体化不可拆的。拆开会导致「用 A 选择器选出的池子配 B 分配器的权重」，与官方规则不符。打包后，选样、打分、限额、赋权全部在一处，参数即规则。

### 1.2 数据从哪来：`factor_panel` 集合

两个策略都不读 CSV、不减本地文件，全部集中在 MongoDB 的 `factor_panel` 集合。策略侧只做一件事——**声明要哪份数据**：

```python
@classmethod
def get_extra_panels(cls):        # 我要 factor_panel
    return ["factor_panel"]

@classmethod
def get_panel_datasets(cls):      # 我要其中哪一个数据集
    return {"factor_panel": "bond_phoenix50"}    # 或 equity_quality_growth
```

`factor_panel` 是一个被多个数据产品共用的集合，所以**必须声明 dataset**。不声明会直接报错：

> 策略声明了面板 'factor_panel' 但未在 get_panel_datasets() 中声明数据集……

**为什么必须隔离**：债券和股票两个数据集的 `as_of_date` 可能撞期（都是季末），不带 dataset 过滤会把另一个域的行并进同一个截面——名次打分的分母 N 被污染、行业内选取会把债券当成候选，而且**不会报错**。

集合的业务主键是三元组 `(dataset, as_of_date, code)`，物理结构：

```json
{
  "dataset": "bond_phoenix50",
  "as_of_date": "2026-09-30",
  "code": "104556.IB",
  "name": "19浙江债58",
  "industry": "金融债/地方债/二永债",
  "data_date": "2026-09-30",
  "total_mv": null,
  "free_float_mv": null,
  "factors": {
    "issuer": "浙江省财政厅",
    "issue_size": 123.45,
    "issuer_size": 6789.0,
    "modified_duration": 2.31
  }
}
```

加载时 `data_feed._load_factor_panel` 会把它摊平成 DataFrame：`index=code`，`industry/total_mv/free_float_mv/data_date/name` 单独成列，`factors` 里的每个键展开成一列。策略拿到的就是这个 DataFrame。

### 1.3 调仓日从哪来：面板期日驱动

两个策略的 `get_execution_schedule()` 都只声明：

```python
{"rebalance_freq": "daily", "execution_delay": 0}
```

**里面没有任何日期常量**。真正的调仓日来自截面本身：

```python
def get_data_feed_options(cls):
    return {"extra_panels": ["factor_panel"], "panel_event_dates": True}
```

`panel_event_dates=True` 会触发 `CompositionPipeline._inject_panel_event_dates()`，把加载到的**所有面板期日**塞进调度的 `event_dates`：

```python
event_dates = sorted({d for dates in self._panel_dates.values() for d in dates})
merged["event_dates"] = event_dates
```

于是：

- 债券策略：28 期截面 → 28 个调仓日（2020-01-02 至 2026-10-08 生效）
- 面板没导入新区间 → 不产生新调仓日，区间末尾沿用最后一期成分，权重自然漂移
- 同一份代码换任何日期区间都能跑，不需要改代码

### 1.4 一次调仓做什么：五步流水线

```
① 定位截面   as_of 之前最近一期（含当日）
                ↓ 同时算滞后：该期日到执行日之间有几个交易日，超限报错
② 初筛       打分因子转数值，剔除任一缺失的候选
                ↓
③ 打分       逐因子打分 → 合成综合分
                ↓
④ 约束      债券：组内单发行人限额 → 组内前 K
             股票：行业前 M → 全体前 N
                ↓
⑤ 赋权       债券：等权 1/N   股票：市值加权 / 等权
                ↓
   返回 weights（reindex 到价格矩阵，没选中的标的权重=0）
```

### 1.5 三条通道，同一份代码

| 通道 | 入口 | 面板注入点 |
|---|---|---|
| 回测 | 策略详情 → 回测 | `DataFeed.from_market_service()` → 引擎 `set_panels()` |
| 日常监控 | 实盘发布后步进 | `monitor_service._load_monitor_panels()` → `_inject_monitor_panels()` |
| 组合子策略 | 组合管理 → 创建组合 | `portfolio_service` 同一链路 |

调仓日同样三通道同源：回测由 `ScheduleResolver` 消费 `event_dates`，监控由 `rebalance_planning._build_event_driven_rebalance_map` 用**同一个** `ScheduleResolver` 消费。

### 1.6 一条贯穿始终的红线：报错，不兜底

`allocate()` 是纯函数：只消费注入的 `prices` 和 `params`，不读文件、不查库。所有异常情况一律 `raise`，不静默处理：

| 情况 | 行为 |
|---|---|
| 截面没注入 | 报错「未注入 factor_panel 截面」 |
| `as_of` 之前无截面 | 报错并给出最早期日 |
| 截面滞后超 `panel_max_lag_days` | 报错并给出滞后天数与期日 |
| 截面缺打分因子列 | 债券走快照模式；**股票直接报错** |
| 出现未声明限额的分组 | 债券直接报错 |
| 选中标的不在价格矩阵 | 报错，**不静默剔除** |
| 市值列缺失或非正 | 股票报错，**不静默改等权** |

这条红线的意义：指数复现类策略一旦静默兜底，净值和官方点位就会出现无法归因的偏差。宁可跑不通，也不给一个「看起来对」的错结果。

## 二、债券券池因子打分指数（`bond_factor_score_index`）

### 2.1 业务定位

复现「中证浙江凤凰行动50指数」的债券券池编制规则：**每季度从全池选 60 只券，等权持有到下个调样日。**

券池分两个组，各有独立的容量约束：

| 分组（`industry`） | 单发行人限额 | 组内入选上限 |
|---|---|---|
| 金融债/地方债/二永债 | 10 只 | 50 只 |
| 其它信用债 | 2 只 | 10 只 |
| **合计** | — | **60 只** |

### 2.2 打分原理：两种打分法，按因子分派

策略对每个打分因子二选一：**名次打分**（看相对排名）或**距目标打分**（看离目标多近）。由 `rank_factors` 参数决定用哪种——在 `rank_factors` 里的走名次，其余走距目标。

#### 名次打分（`rank_score`）

$$\text{score} = 100 \times \frac{\text{rank}_{\max}(x) - 1}{N - 1}$$

```python
r = vals.rank(method="max", ascending=True)   # 并列取最大名次 → 同值同分
return 100.0 * (r - 1.0) / (n - 1.0)
```

- 值最大的得 **100 分**，值最小的得 **0 分**，其余线性分布在中间
- `method="max"` 保证并列项同分（例：三只券并列第 5，都得 5 名，同分）
- **分母锁死 `N-1`**，不是 `max(rank) - min(rank)`。若用后者，最末的并列组会被抬到 0 分以上，整体尺度偏差 `100/(N-1)`
- `N < 2` 直接报错，不产生 inf

#### 距目标打分（`target_distance_score`）

$$\text{score} = \max\left(0,\ 100 \times \left(1 - \frac{|x - \text{target}|}{\text{span}}\right)\right)$$

```python
dev = (s - target).abs()
return np.maximum(0.0, 100.0 * (1.0 - dev / span))
```

- 命中目标 = **100 分**
- 偏离达到 `span` = **0 分**
- 超过 `span` 仍为 0（`np.maximum` 截断，不出现负分）
- `span <= 0` 直接报错

#### 默认配置下的实际效果

| 因子 | 打分法 | 权重 | 含义 |
|---|---|---|---|
| `issue_size` 债券发行规模 | 名次 | 0.2 | 单只券发得越大越好 |
| `issuer_size` 主体发行规模 | 名次 | 0.2 | 发行人整体体量越大越好 |
| `modified_duration` 修正久期 | 距目标 | **0.6** | 越接近 2.5 年越好，偏离 7.5 年归零 |

综合分 = Σ(权重 × 单因子分)，满分 100。久期占 60% 权重，是这条策略的主控变量——它决定了组合的利率敏感度中枢。

> **注意名次分的分母**：`rank_score` 在**整个候选截面**上计算（当前是 548 只全池），不是在分组内。所以「其它信用债」的分数天然低于「金融债/地方债/二永债」（主体规模小、名次靠后），但选样是**组内排序取前 K**，绝对值不影响结果。

### 2.3 三层筛选：从 548 到 60

```
① 初筛   dropna(打分因子)  → 548 只全部保留（当前数据无缺失）
② 限额   组内按 issuer 归并，累次排名 ≤ cap 的保留  → 淘汰 413，剩 135
③ 前 K   组内按综合分降序取前 K                      → 入选 60
```

#### 第二层：单发行人限额（`_issuer_cap`）

按 `industry` 分组，组内再按 `issuer` 归并，同一发行人的多只券按综合分降序排，「第几只」超过 cap 就淘汰：

```python
for g in groups:
    sub = tmp[tmp["_group"] == g].sort_values(
        by=[_SCORE_COL, _CODE_COL], ascending=[False, True], kind="mergesort")
    sub["_rn"] = sub.groupby(_ISSUER_COL).cumcount() + 1
    kept.append(sub[sub["_rn"] <= cfg["pool_caps"][g]])
```

**关键点**：这不是「每家发行人最多 N 只」的简单截断，而是**按得分排队**——同一发行人得分高的券优先保留，得分低的被挤掉。

实测：548 → 135，淘汰 **413 只**——绝大多数是因为一个发行人发了太多只券。

#### 第三层：分组前 K（`_select_topk`）

组内按 `(综合分 降序, 代码 升序)` 稳定排序后取前 K。用 `kind="mergesort"` 保证同分时结果可复现（不随 pandas 版本变）。

#### 未声明分组即报错

```python
unknown = [g for g in groups if g not in cfg["pool_caps"] or g not in cfg["pool_topk"]]
if unknown:
    raise ValueError(f"...截面分组 {unknown} 未在 pool_caps/pool_topk 声明限额与选取数量...")
```

这是刻意的：**新出现的券池分组必须显式配置限额**，系统不会猜一个默认值。

### 2.4 双模式：快照 vs 打分

历史 27 期只有官方成分名单、没有逐券因子值。策略用一个判定自动切换：

```python
@staticmethod
def _is_constituent_snapshot(panel, cfg):
    return any(f not in panel.columns for f in cfg["score_factors"])
```

| 模式 | 触发条件 | 行为 | `selection_source` |
|---|---|---|---|
| 成分快照 | 截面缺任一拍分因子列 | **全截面入选 + 等权**，跳过打分/限额/前K | `constituent_snapshot` |
| 因子打分 | 打分因子列齐备 | 完整五步流水线 | `factor_score` |

**为什么这样设计**：历史期拿不到逐券因子，只能用官方已公布成分反推持仓——这是「复现」而非「兜底」。审计字段 `selection_source` 明示当前期走的是哪条路，可追溯。

实测 28 期分布：

| 期数 | as_of 范围 | 行数 | 分组 | 走哪条路 |
|---|---|---|---|---|
| 27 | 2019-12-31 ~ 2026-06-30 | 50~60 | `历史成分` | 快照 |
| 1 | 2026-09-30 | **548** | 金融债/地方债/二永债 427 + 其它信用债 121 | 打分 |

> **边界提示**：快照模式**不校验分组**。历史期的 `industry="历史成分"` 并不在 `pool_caps/pool_topk` 里，但因为走快照分支（不经过 `_issuer_cap`），不会报错。若将来新导入的一期**同时具备因子列又出现「历史成分」分组**，会在限额环节报错——届时需把该分组补进 `pool_caps`/`pool_topk`。

### 2.5 赋权：严格等权 1/N

```python
per = 1.0 / len(uniq)
weights = {code: per for code in uniq}
residual = 1.0 - sum(weights.values())
if abs(residual) > 1e-8:            # 只在浮点残差超容差时才处理
    weights[uniq[0]] += residual     # 归代码最小的券
```

**不做十进位舍入**。官方指数按 `round(1/N, 8)` 落权重，系统严格 1/N——这个差异就是净值与官方点位残差（`2.272e-11`）的来源之一，属于已知口径差，不做迁就。

### 2.6 调仓时点：决策日收盘成交

指数编制里 `as_of` 是**决策日**（生效日前一交易日）：

- 决策日收盘按新权重成交
- 新权重自**生效日**起计收益
- 效果等于「生效日当天的收益用新权重」

这正是 `execution_delay=0` + `panel_event_dates` 的组合效果，不需要额外偏移。

### 2.7 参数全表（12 项）

| # | 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|---|
| 1 | `score_factors` | text | `issue_size,issuer_size,modified_duration` | 打分因子键，**顺序与 `score_weights` 一一对应** |
| 2 | `score_weights` | text | `0.2,0.2,0.6` | 综合分权重，**个数须与因子数一致**，否则报错 |
| 3 | `rank_factors` | text | `issue_size,issuer_size` | 走名次打分的因子；不在其中的走距目标打分 |
| 4 | `duration_target` | number | `2.5` | 距目标打分的目标值（修正久期，年），范围 [-100, 100]，步长 0.1 |
| 5 | `duration_span` | number | `7.5` | 距目标打分的扣分全距，范围 [0.01, 100]，步长 0.1 |
| 6 | `pool_caps` | text | `其它信用债:2,金融债/地方债/二永债:10` | 分组→单发行人入选上限，格式 `分组:整数` |
| 7 | `pool_topk` | text | `其它信用债:10,金融债/地方债/二永债:50` | 分组→组内入选数量，格式同上 |
| 8 | `panel_max_lag_days` | number | `5` | 截面相对执行日的最大滞后交易日，范围 [0, 120] |
| 9 | `execution_delay` | number | `0` | 信号日→成交日延迟（T+N），范围 [0, 10] |
| 10 | `preserve_price_gaps` | boolean | `false` | 缺日保真：信号计算用保留 NaN 的价格矩阵 |
| 11 | `inception_weights` | dict | `{}` | 期初建仓权重（代码→权重），留空则空仓等首次调仓 |
| 12 | `inception_weights_auto_normalize` | boolean | `false` | 期初权重之和不为 1 时是否自动归一化 |

> **`panel_max_lag_days` 怎么定**：默认 5 只适用于「回测起点贴着调样日」的场景（首期 2019-12-31 到首个交易日 2020-01-02，滞后 1 日）。而季频截面在季度中间调样时，最近一期可能是**上一个季末**，滞后约 60 个交易日。**当前该模型实际配置为 70**，就是为了覆盖一个完整季度间隔。
>
> 调低这个值不是「更严谨」，而是让非调样日起点的回测直接报错。想严格只在调样日调仓，靠的是 `panel_event_dates` 已经把调仓日锁到面板期日，`panel_max_lag_days` 只是防呆上限。

### 2.8 数据要求

#### 价格数据

| 项 | 要求 |
|---|---|
| 资产主数据 | 必须覆盖**券池可选全集**（当前 387 只），维度 `固收 / 债券 / 指数型` |
| 行情口径 | 每券「全收益价格指数」（基期 100），**不是成交价**，不可用于撮合或估值核对 |
| 稀疏存储 | 只写成分日 + 基期日；非成分日不写行，由 `sanitize_prices` 前向平延 |
| 为什么必须全选 387 | 季度调样会在其间轮换。池子给窄了，某个期日会触发「入选券不在资产池」报错 |

#### 截面数据

必填列（缺任一列整行拒绝）：

| 字段 | 可接受的列名 |
|---|---|
| `as_of_date` | `日期` / `权重生效日` / `调仓日` / `生效日期` / `as_of_date` |
| `code` | `代码` / `股票代码` / `证券代码` / `债券代码` / `thscode` / `wind_code` |
| `industry` | `行业` / `所属行业` / `中证三级行业` / `申万行业` / **`券池`** / `industry` |

> `industry` 有 `券池` / `券池*` 这两个别名——债券场景下用「券池」作列名即可，不必改成「行业」。

可选固定列：`data_date`（`因子取数日`/`数据日期`/`财报日`/`报告期`）、`name`（`简称`/`名称`）

债券专有因子列 → 英文键映射：

| 中文列名 | 因子键 | 类型 |
|---|---|---|
| 债务主体 / 发行人 | `issuer` | **类别因子（文本）** |
| 债券发行规模 | `issue_size` | 数值 |
| 主体发行规模 | `issuer_size` | 数值 |
| 修正久期 | `modified_duration` | 数值 |

`issuer` 必须在 `FACTOR_CATEGORICAL_KEYS_BY_DATASET["bond_phoenix50"]` 里登记（已登记），否则导入时会按数值解析失败被置空，策略侧读不到该键直接报错。

### 2.9 配置步骤

**① 准备截面数据**

走前端「数据分析 → 因子截面」：

1. 数据集下拉选 `bond_phoenix50`
2. 下载导入模板，按上表填列
3. 上传 → `POST /api/v1/factor-panel/import`

## 三、因子打分指数（`factor_score_index`）

### 3.1 业务定位

复现「A股质量成长」选股指数：**每期从候选池按质量成长因子打分选 50 只，按市值加权持有。**

### 3.2 打分原理：三步归一化

#### 第一步：winsorize 截断极值

$$\tilde{x} = \text{clip}(x,\ \mu - k\sigma,\ \mu + k\sigma)$$

```python
if k > 0:
    mean, std = col.mean(), col.std()      # ddof=1
    clipped = col.clip(lower=mean - k*std, upper=mean + k*std)
else:
    clipped = col                          # k=0 不截断
```

- 默认 `k=2.0`：超出「均值 ± 2 倍标准差」的值压到边界
- 目的：防止一两个极端值把 min-max 的尺度拉爆（例如某只股票 PE 是负的 -500，不截断会把整个区间压扁）
- `k=0` 完全关闭截断

#### 第二步：min-max 归一化到 [0, 1]

正向因子（值越大越好）：

$$\text{score} = \frac{\tilde{x} - \min}{\max - \min}$$

反向因子（值越小越好，如 PE）：

$$\text{score} = \frac{\max - \tilde{x}}{\max - \min}$$

```python
fmax, fmin = clipped.max(), clipped.min()
denom = fmax - fmin
if denom == 0 or pd.isna(denom):
    out[sc] = 0.0                    # 全列同值 → 全部记 0 分
elif f in reverse_factors:
    base = (fmax - clipped) / denom
    out[sc] = np.where(clipped > 0, base, 0.0) if reverse_zero_floor else base
else:
    out[sc] = (clipped - fmin) / denom
```

两个细节：

- **全列同值**（`denom == 0`）：该因子对所有候选记 0 分，不产生 NaN/inf
- **反向因子非正记零**（`reverse_zero_floor=True`）：反向因子截断后值 ≤ 0 时直接记 0 分。这是针对扣非 PE 的——亏损股 PE 为负，按 `(max-x)/(max-min)` 反而会得高分，必须单独拦截

#### 第三步：综合分 = 各因子得分相加

```python
out[_SCORE_COL] = out[score_cols].sum(axis=1)
```

**注意是「相加」不是「加权平均」**：

- 每个因子得分 ∈ [0, 1]，3 个因子相加 → 综合分 ∈ [0, 3]
- 相加与加权平均（权重相等时）的**排序完全等价**，只是尺度不同
- 但相加使得「增加一个因子」会改变分数尺度——审计日志里综合分区间会跟着变，属正常

#### 默认三因子

| 因子键 | 中文 | 方向 | 说明 |
|---|---|---|---|
| `profit_yoy_sq_dn` | 单季度扣非净利润同比增速 | 正向 | 越能赚钱越好 |
| `pe_ttm_dn` | 扣非 PE（TTM） | **反向** | 越便宜越好，负值记 0 分 |
| `dividend_yield_ttm` | 股息率 TTM | 正向 | 分红越多越好 |

### 3.3 两级筛选：从 203 到 50

```
① 初筛   dropna(打分因子) + 可选正值筛选
② 行业限额  每个行业按综合分取前 M（默认 5）
③ 全体前 N  按综合分取前 50
```

#### 行业限额（`_industry_cap`）

```python
ranked = tmp.sort_values(by=[_INDUSTRY_COL, _SCORE_COL, _CODE_COL],
                         ascending=[True, False, True], kind="mergesort")
capped = ranked.groupby(_INDUSTRY_COL, sort=False).head(top_n)
```

- `industry_top_n = 0` → **跳过整个环节**，不做行业约束
- 默认 5 → 每个行业最多 5 只，防止单一行业过度集中
- 同分按代码升序，结果确定

#### 全体前 N（`_select_top`）

行业限额通过后，全体按综合分降序取 `select_count`（默认 50）。`select_count <= 0` 直接报错。

#### 可选：正值筛选

`screen_positive_factors` 填因子键后，额外要求这些因子取值 > 0：

```python
df = df[(df[positive] > 0).all(axis=1)]
```

例如想剔除「营收负增长」的股票，填 `revenue_yoy_sq` 即可。留空则只按打分因子缺失剔除。

### 3.4 赋权：三种口径

```python
def cap_weights(market_caps):
    ranked = sorted(market_caps.items(), key=lambda item: (-item[1], item[0]))
    weights = {code: round(mv / total, 8) for code, mv in ranked}
    residual = round(1 - sum(weights.values()), 8)
    weights[ranked[0][0]] = round(weights[ranked[0][0]] + residual, 8)  # 尾差归市值最大股
```

| `weight_method` | 用哪列 | 说明 |
|---|---|---|
| `market_cap`（默认） | `total_mv` | 总市值加权，指数默认口径 |
| `free_float_cap` | `free_float_mv` | 自由流通市值加权 |
| `equal` | 无 | 等权 1/N（内部对每只传相同市值实现） |

**尾差归市值最大股**（不是代码最小股），且排序保证「市值降序、同值代码升序」，尾差永远落在同一只上，可复现。

**市值缺失即报错，不静默改等权**：

```python
if pd.isna(val) or float(val) <= 0:
    invalid.append(code)
...
raise ValueError(f"...以下选中标的缺少有效 {col}（须 >0）：{invalid}...")
```

| **增补键** | `issuer`（类别因子/文本） | 无 |
| **赋权** | 等权 1/N，尾差归代码最小 | 市值/等权，尾差归市值最大 |
| **市值依赖** | 无 | `market_cap`/`free_float_cap` 时需要 |

5. 都用 `_audit()` 把当期指标写进实例状态，供 `compute_monitoring_metrics()` 暴露到前端监控页

## 七、一句话总结

**这两个策略的本质是「把指数编制规则写成参数」。**

规则怎么变，就改参数——换打分因子、调权重、改限额、换选取数量，都不需要改代码、不触碰表结构。代价是规则必须自洽：参数互相矛盾（权重个数与因子数不一致、分组键不匹配、限额为负）在**开跑前**就会被契约门禁拦下，跑起来之后的每一个异常（截面缺失、滞后超限、标的不在池中、市值缺失）都会**明确报错而不是悄悄兜底**。

这条设计取舍的根因是：指数复现类策略的输出要能与官方点位逐点对账，任何静默兜底都会制造无法归因的偏差。宁可让你看到一条清晰的报错，也不给你一条「看起来涨得不错」的假净值。
