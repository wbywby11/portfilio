# 日常监控模块说明

本文档描述系统日常监控模块（app/monitor）的运行机制：日级步进推演、信号检测、日报生成与监控注册管理。监控与回测共用同一引擎，是"策略上线后每日跟踪"的核心设施。

## 一、模块定位与职责分离

监控与回测**职责分离、引擎复用**：
- 回测：历史全区间一次性推演，产出策略评估；
- 监控：从建仓日（inception_date）至今逐日步进，跟踪策略/组合的实盘状态、检测再平衡与风险信号；
- 二者共用 BacktestEngine 的信号/执行/风控逻辑（通过 `engine_adapter.py` 适配），保证口径一致。

## 二、核心组件

| 组件 | 文件 | 职责 |
|---|---|---|
| 日级步进器 | `daily_stepper.py` | 逐交易日推进监控状态，增量计算（不每日全量重跑） |
| 引擎适配器 | `engine_adapter.py` | 把监控任务适配为 BacktestEngine 可执行的形态 |
| 信号检测器 | `signal_detector.py` | 检测调仓信号、波动越限、偏离阈值等事件 |
| 波动率计算 | `volatility_calculator.py` | 监控用实时波动率估计 |
| 再平衡计划 | `rebalance_planning.py` | 计算下一次调仓的目标权重与交易清单 |
| 报告生成器 | `report_generator.py` | 生成监控日报（落 `monitor_daily_reports` 集合） |
| 组合跟踪器 | `portfolio_tracker.py` | 组合级持仓/净值跟踪 |
| 监控查询 | `monitor_query.py` | 监控状态与历史日报查询 |
| 数据供给 | `data_provider.py` | 从行情集合取监控所需价格数据 |
| 手动预设 | `manual_preset.py` | 手动干预/预设监控参数 |

## 三、监控注册与生命周期

**注册机制**：在 `monitored_strategies` 集合为策略模型建立监控实例，记录含 `source_ref`（指向模型 ID）、创建时间等。

**状态存储**：监控运行状态落 `monitor_states` 集合（支持断点续跑——增量步进依赖上次状态）。

**日报输出**：每日步进结果落 `monitor_daily_reports`，前端监控页面按日展示信号与指标。

**运行约束**：
- 建仓日（inception_date）为 None 的模型需先补设，监控从建仓日推演；
- 行情数据滞后会导致监控"陈旧"判定（如数据截止日距今超阈值，日报会提示数据时效问题）；
- 监控引擎**不支持 portfolio_composite 类型**（母组合）——对母组合点监控会产生无效注册并反复 404，母组合监控需走组合专用路径（`portfolio_backtest_monitor.py`）。

## 四、与相关模块的关系

```
strategy_models（策略模型）
    ↓ 注册监控实例
monitored_strategies（监控注册）
    ↓ daily_stepper 逐日步进（复用 BacktestEngine）
monitor_states（状态快照）+ monitor_daily_reports（日报）
    ↓
前端监控页面 / Agent query_monitors 工具
```

- 策略发布实盘后，实盘变更记录落 `strategy_live_change_logs`、实盘监控记录落 `strategy_live_monitoring_records`；
- Agent 可通过 `query_monitors` 查询监控状态与日报，通过 `update_monitor_config` 调整监控配置（写操作需确认）。

## 五、常见问题

1. **监控反复 404**：多为对母组合（portfolio_composite）注册了监控，监控引擎不支持该类型；
2. **日报数据陈旧**：行情数据未及时导入，先补数据再重跑步进；
3. **初始化兼容**：旧版数据格式初始化时按现有字段兜底，缺失字段用默认值。
