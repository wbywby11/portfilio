# 权重计算逻辑与对应代码

## 一、整体调用链

```
engine.run()
  → 每个调仓日: self._strategy.generate_target_weights(history, as_of=time)
      若策略为 StrategyAdapterWithSelection（启用资产选择）:
        → strategy_api.StrategyAdapterWithSelection.generate_target_weights
          1. 资产选择: selection_service.select_assets(...) → selected_assets / active_assets
          2. selected_history = history_prices[active_assets]
          3. weights_series = base_strategy._impl.allocate(selected_history, **strategy_params)  ← 核心权重计算
          4. 将权重扩到全候选池（未选中资产置 0）→ final_weights
          5. _log_rebalance_weights(...) 打印
          6. return TargetWeightSignal(time=as_of, target_weights=final_weights)
      若未启用资产选择:
        → StrategiesWrapper.generate_target_weights
          → weights = self._impl.allocate(history_prices, **self._params)
          → return TargetWeightSignal(time=as_of, target_weights=weights_dict)
  → 风控: risk.apply_risk_checks(target_signal)
  → 执行调仓: 指数净值模式 或 传统模式
```

**对应代码位置：**

| 环节 | 文件 | 行号/方法 |
|------|------|-----------|
| 调仓日循环、调用策略生成权重 | `app/backtesting/engine.py` | 约 364 行 `target_signal = self._strategy.generate_target_weights(history, as_of=time)` |
| 资产选择 + 调用 allocate + 扩权 + 打印 | `app/backtesting/strategy_api.py` | `StrategyAdapterWithSelection.generate_target_weights`（约 346–490 行） |
| 调仓日权重打印 | `app/backtesting/strategy_api.py` | `_log_rebalance_weights`（约 16–31 行） |
| 核心权重计算（风险预算+目标波动率） | `app/strategies/models/risk_budget_target_vol.py` | `RiskBudgetTargetVolStrategy.allocate`（约 132–376 行） |

## 二、StrategyAdapterWithSelection：权重由谁算、怎么扩到全池

**文件：** `app/backtesting/strategy_api.py`

1. **资产选择**  
   - 用 `selection_service.select_assets(selector_type, prices=history_prices, n_assets=n_selected, **selection_params)` 得到 `selected_assets`。  
   - 对非 momentum_reversal 可选做「池内再选」得到 `active_assets`；momentum_reversal 时 `active_assets = selected_assets`。  
   - `selected_history = history_prices[active_assets]`，只含参与分配的资产。

2. **调用策略算权重**  
   - 只对「参与分配」的资产算权重，即对 `selected_history` 调用基础策略的 `allocate`：  
   - `weights_series = self._base_strategy._impl.allocate(selected_history, **strategy_params)`  
   - 这里 `allocate` 的输入列 = `active_assets`，输出权重的索引也是这些资产，且通常权重和为 1（或按杠杆允许 >1）。

3. **扩到全候选池**  
   - `weights_dict = weights_series.to_dict()` 只有 active 资产。  
   - 对 `self._thscodes` 中每个 `code`，若不在 `target_weights` 里则置 0：  
     `final_weights = {code: target_weights.get(code, 0.0) for code in self._thscodes}`  
   - 因此：**权重计算只在 active 资产上进行，扩到全池时未选中资产为 0。**

4. **打印**  
   - `_log_rebalance_weights(as_of, final_weights, self._thscodes)` 在返回前打印本次调仓的权重。

## 三、RiskBudgetTargetVolStrategy.allocate：核心公式与步骤

**文件：** `app/strategies/models/risk_budget_target_vol.py`，方法 `allocate(self, prices: pd.DataFrame, **params) -> pd.Series`

输入：`prices` 为本次参与分配的资产价格（行=日期，列=资产代码），通常已由上层限定为 `selected_history`；`params` 中含目标波动率、风险预算、杠杆、单资产上限等。

### 步骤 1：参数与有效资产

- `target_vol`：目标年化波动率（默认 0.05）。  
- `risk_budget_both` / `risk_budget_single`：交集/单一模型风险预算（默认 0.25 / 0.125）。  
- `max_total_leverage`：最大杠杆倍数（默认 4）。  
- `max_weight_dict`：单资产最大权重（未配置的资产用默认上限，如 0.1）。  
- `_asset_tags`：资产标签（both / momentum / reversal），用于分配风险预算。  
- 按 `min_history_days` / `lookback_days` 与实际数据长度做「截取数据、放宽有效天数」，得到 `valid_assets`，`prices` 只保留 `valid_assets`。

### 步骤 2：风险预算分配

- 对每个 `valid_assets` 中的资产：  
  - `tag == "both"` → `risk_budget = risk_budget_both`  
  - `tag in ["momentum","reversal"]` → `risk_budget = risk_budget_single`  
  - 否则 → `risk_budget = 1.0 / n_assets`（等权风险预算）

### 步骤 3：已实现波动率

- 使用窗口 `vol_windows = [22, 65, 130]`，对每个资产算滚动年化波动率，取**最大值**作为该资产的 `realized_vol`（与编制规则一致）。  
- 代码：`compute_asset_rolling_volatility(prices, windows=vol_windows, annualization_factor=260)`。

### 步骤 4：初始权重（风险预算 × 目标波动率 / 波动率）

- 对每个资产：  
  `w_init[asset] = risk_budget[asset] * target_vol / realized_vol[asset]`  
- 即：**风险预算越大、目标波动率越高、资产波动率越低，初始权重越大。**

### 步骤 5：组合波动率

- 用当前 `weights_init` 和收益率，算组合的滚动波动率（同样 22/65/130 取最大）：  
  `portfolio_vol = compute_portfolio_volatility(returns, weights=weights_init, windows=vol_windows, ...)`。

### 步骤 6：三重约束缩放

- **约束 1（波动率）：**  
  `vol_scale = target_vol / portfolio_vol`（若 portfolio_vol>0），使按比例缩放后组合波动率约等于 target_vol。  
- **约束 2（总杠杆）：**  
  `leverage_scale = max_total_leverage / weights_init.sum()`，使权重和不超过 max_total_leverage。  
- **约束 3（单资产上限）：**  
  对每个资产，若 `weights_init[asset] > 0`，则 `scale = max_weight_dict.get(asset, default_max_weight) / weights_init[asset]`；  
  取所有这类 scale 的最小值 `weight_scale`，保证任意资产不超过其最大权重。  
- **综合缩放：**  
  `final_scale = min(vol_scale, leverage_scale, weight_scale)`  
  `weights_final = weights_init * final_scale`。

### 步骤 7：杠杆上限再归一化（可选)

- 若 `weights_final.sum() > max_total_leverage`，再整体缩放：  
  `weights_final = weights_final * (max_total_leverage / weights_final.sum())`。  
- 返回 `weights_final`（索引为 valid_assets，和为 1 或 max_total_leverage）。

## 四、公式小结（RiskBudgetTargetVolStrategy）

| 步骤 | 公式/逻辑 | 代码位置（约） |
|------|-----------|----------------|
| 风险预算 | both=0.25, single=0.125, 其他=1/n | 287–301 行 |
| 初始权重 | `w_init = risk_budget * target_vol / realized_vol` | 324–329 行 |
| 组合波动率 | 22/65/130 日滚动波动率取最大 | 331–336 行 |
| 波动率约束 | `vol_scale = target_vol / portfolio_vol` | 341 行 |
| 杠杆约束 | `leverage_scale = max_total_leverage / sum(w_init)` | 344–345 行 |
| 单资产约束 | 每资产 scale = max_weight / w_init，取最小 | 354–371 行 |
| 最终缩放 | `final_scale = min(vol_scale, leverage_scale, weight_scale)`，`weights_final = w_init * final_scale` | 368–371 行 |
| 杠杆再归一化 | 若 sum>max_total_leverage 则按比例缩放到 max_total_leverage | 374–375 行 |

## 五、为何会出现「权重和 > 1」

- 当 `max_total_leverage > 1` 且三重约束后 `weights_final.sum()` 仍大于 1 时，不会强制缩放到 1，只会在超过 `max_total_leverage` 时缩放到 `max_total_leverage`。  
- 因此权重和可以介于 1 与 `max_total_leverage` 之间，对应「杠杆仓位」；前台展示时纵轴需支持大于 1（按实际权重和设上限）。
