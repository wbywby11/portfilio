# 日志打印相关修改文件梳理

本文档梳理与 **loguru 接入、启动日志、切分存储** 相关的所有文件，便于排查与回退。

---

## 一、本次接入直接涉及的文件

### 1. 新增

| 文件 | 说明 |
|------|------|
| **`app/config/logging_config.py`** | loguru 配置模块：`setup_logging()`，配置控制台 + 按天切分文件（`logs/app_YYYY-MM-DD.log`）、保留 7 天。 |

### 2. 修改

| 文件 | 修改内容 |
|------|----------|
| **`main.py`** | ① 顶部增加 `from app.config.logging_config import setup_logging` 与 `setup_logging()`；② `on_startup` 内使用 `from loguru import logger`，原 `print` 改为 `logger.info` / `logger.exception` / `logger.error`，并增加「应用启动成功」「应用启动失败」日志；③ `on_shutdown` 内使用 `logger`，增加「应用已关闭」日志。 |
| **`app/config/database.py`** | ① 顶部增加 `from loguru import logger`；② `connect()` 中 `print(...)` 改为 `logger.info("数据库连接成功: {}", settings.DATABASE_NAME)`；③ `close()` 中 `print(...)` 改为 `logger.info("数据库连接已关闭")`。 |
| **`requirements.txt`** | 增加依赖 `loguru>=0.7.0`（及注释 `# 日志`）。 |
| **`.gitignore`** | 增加 `logs/` 及注释，避免提交日志目录。 |

### 3. 回退与说明文档

| 文件 | 说明 |
|------|------|
| **`docs/loguru_rollback_修改清单.md`** | 回退步骤与每文件还原说明，便于回退。 |

## 二、项目中其它使用 logger 的文件（未在本次修改）

以下文件在接入前已使用 `logging` 或 `loguru` 的 `logger`，接入后其输出会统一走 loguru 的控制台与文件，**本次未改这些文件的代码**：

| 文件 | 用途 |
|------|------|
| **`app/services/portfolio_service.py`** | 追溯回测完成、回测期间、交易日数、Snapshots 详情、核心业绩指标等 `logger.info`。 |
| **`app/backtesting/strategy_api.py`** | 策略相关 `logger.info`。 |
| **`app/services/scheduler_service.py`** | 定时任务启动/停止、任务开始/完成/失败等 `logger.info` / `logger.error`。 |

若这些模块使用 `logging.getLogger(__name__)`，需在 `setup_logging()` 中增加对标准库 logging 的拦截，才会写入 loguru 文件；若已直接使用 `from loguru import logger`，则无需改配置。

## 四、日志输出位置

- **控制台**：所有 `logger.*` 输出到 stderr，格式带时间、级别、模块/函数/行号。
- **文件**：项目根目录下 `logs/app_YYYY-MM-DD.log`，按天切分（`rotation="00:00"`），默认保留 7 天（`retention="7 days"`）。

如需调整目录、保留天数或级别，可修改 `app/config/logging_config.py` 中 `setup_logging()` 的参数或实现。
