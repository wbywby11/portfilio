## 📄 第一页｜研发 · 构建

**标题**：指数全生命周期管理（上）—— 研发与构建

**主视觉**：白底红字，左「研发」右「构建」两个阶段框，各框内列出实际做的事；红箭头串起"素材积累 → 组装 → 回测对比 → 入库"

### 研发阶段 · 我们做什么
- **自研 + 与外部机构交流**，形成 **20 多个策略模型**，沉淀在系统模型库、可复用
- **数据积累丰富**：覆盖期货、国内外市场（指数型 / 现货型 / 期货型三类工具，人民币 / 美元 / 日元多币种），可选素材充足
- 每个策略经回测验证后入库，**参数与版本可追溯**

### 构建阶段 · 我们做什么
- 系统化"**搭积木**"组装策略：如 **风险平价（配多少）+ 夏普因子（选什么）+ 波动率控制（怎么控）** 三段拼装
- **回测框架支持多策略绩效对比**，横向比较后择优构建
- 新指数直接**复用已入库的模型与方法**

### 这一页要展现
指数研究阶段，我们**素材充分**（20+ 策略模型 + 期货 / 国内外数据），且**能实际回测、做对比分析**。

**本页数字**：20+ 策略模型　·　3 类工具 × 多币种数据　·　三段拼装　·　多策略回测对比

## 📄 第二页｜运营 · 日常管理

**标题**：指数全生命周期管理（下）—— 运营与日常管理

**主视觉**：白底红字，左「运营」右「日常管理」承接 P1；中部画出操作指令流转（信号日 → 执行日），主观指令走"记录 → 审批 → 追踪"支线

### 运营阶段 · 我们做什么
- 系统按策略**算出指数操作指令**，分三类：月度调仓 / 波动率重置 / 主观调仓
- **每日计算、持续跟踪**：信号日生成指令（pending）→ 执行日落地（executed）
- **日常监控全公司范围开放**：全员可查看、参与维护、发现问题

### 日常管理阶段 · 我们做什么
- 操作指令**具象化**：生成目标权重与持仓金额（人民币 / 本币），**对接产品**
- **通过数据接入 API 对接上游**：本系统的通用数据接入 Hub（连接器机制）从外部数据中台等上游，接入真实产品数据（实际持仓、净值），理论 / 实际**双轨对照**
- **主观指令记录功能**：人工主观调仓单独记录，须**提交审批**（pending → executed / cancelled），并**追踪执行效果**（时间戳 + 关联指令 + 实际净值）

### 这一页要展现
运营阶段系统**自动算指令、每日跟踪、开放监控**；日常管理**指令对接产品、同步真实数据、主观调仓有审批有追踪**。

**本页数字**：3 类操作指令　·　每日计算跟踪　·　理论 / 实际双轨　·　主观指令审批留痕

## 实证支撑（每条都有代码依据，非主观描述）

| 大纲表述 | 代码实证 |
|---|---|
| 20+ 策略模型 | `STRATEGY_MANIFEST`（21 个注册模板） |
| 期货 / 国内外数据 | `asset.py` 三维分类（`InstrumentType` 含期货型、`Currency` 含 CNH/USD/JPY）＋ `price_repository` |
| 搭积木组装（风险平价 + 夏普 + 波动率控制） | 三支柱 Selection→Allocation→Control（`risk_parity` 分配器、`sharpe` 选择器） |
| 多策略回测对比 | 回测平台 + `MultiStrategyComparison` |
| 系统算三类操作指令 | `OperationType`（`monthly_rebalance` / `vol_reset` / `subjective`）、`MonitorOperation` |
| 每日计算、信号日→执行日 | `MonitorOperation`（`signal_date`→`execute_date`，`pending`→`executed`） |
| 指令具象化对接产品 | `PositionDetail`（目标权重 + `position_cny`/`position_local`）、`product_layer.py` |
| API 接入外部数据（含真实产品数据） | `data_hub.py`「通用数据接入 Hub API」(`/api/v1/data-hub`) + 连接器机制（`data_connector`、`import_from_upstream`）；行情经 `price_importer` 导入、`price_repository` 读收口；`product_layer` 产品层对接 |
| 理论 / 实际双轨 | `portfolio_dual_track.build_portfolio_actual_nav`（实际净值含主观调整） |
| 主观指令记录 + 审批 + 追踪 | `SubjectiveOverride` / `OverrideStatus`（`pending`→`executed`/`cancelled`）、`created_at`/`executed_at`、`linked_operation_id`、`mark_override_executed` |

> **系统边界（重要）**：数据中台是**外部上游系统**，不在本系统范围；本系统的角色是做**数据接入 API**（通用数据接入 Hub + 连接器机制）从上游接入数据——须表述为"我们接入数据"，而非"我们拥有数据中台"。
>
> **未找到系统实证、按业务事实写入的**：①「日常监控全公司范围开放」属部署 / 账号层面的开放策略（用户陈述）；②管理指数的**数量 / 规模**——系统无实证，留待业务侧填，**不编造**。
